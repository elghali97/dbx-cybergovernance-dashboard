# Development

## Repository layout

```
databricks.yml                 bundle definition: targets prod (default) and dev
config.yml                     deployment settings (the only file to edit to deploy)
deploy.sh                      one-command installer (wraps tools/install.py)
resources/
  jobs.yml                     refresh job (tasks refresh → publish), the only bundle resource
src/
  refresh.py                   refresh task: builds the tables from system tables
  publish.py                   publish task: creates / updates the dashboard and the Genie agent from the templates
  sql/10_sources.sql           src_* views over system tables
  sql/20_semantic.sql          topic views over audit_security_events
  sql/30_findings.sql          checks, findings, score, trend, activity KPIs
  dashboards/*.lvdash.json     dashboard template   ← generated by tools/build_dashboard.py
  genie/*.genie.json           Genie agent template ← generated by tools/build_genie.py
setup/grants.sql               one-time prerequisites (metastore admin)
docs/                          deployment, architecture, checks, weekly report, development
tools/
  install.py                   installer behind deploy.sh
  links.py                     prints the dashboard / Genie agent / job links of a deployment
  build_dashboard.py           generates the dashboard (datasets, pages, theme)
  build_genie.py               generates the Genie agent (tables, instructions, example SQL)
  check_widgets.py             runs every dashboard widget query against a deployed schema
  apply.py, q.py               run SQL files / statements on a warehouse while iterating on views
.github/workflows/             ci.yml (offline checks), deploy.yml (manual deployment)
```

## Workflow

```bash
export DATABRICKS_CONFIG_PROFILE=<profile> DATABRICKS_WAREHOUSE_ID=<warehouse id>

# 1. Change SQL (src/sql), the dashboard (tools/build_dashboard.py) or the Genie agent (tools/build_genie.py)
python3 tools/build_dashboard.py && python3 tools/build_genie.py

# 2. Deploy a personal copy and refresh it
./deploy.sh --target dev --yes

# 3. Check every dashboard query against your dev schema
CATALOG=<catalog> SCHEMA=security_posture_dev python3 tools/check_widgets.py
```

To iterate on views without running the job:
`CATALOG=<catalog> SCHEMA=security_posture_dev python3 tools/apply.py src/sql/20_semantic.sql`.

## Conventions

- **Dashboard**: follows the AI/BI dashboard JSON spec.
  - 12-column `GRID_V1` grid; counter / table / filter widgets are version 2, charts version 3.
  - Datasets use bare object names; the bundle sets the catalog / schema.
  - Counters only `SUM` / `MAX` numeric columns of datasets pre-aggregated by their filter dimensions; no
    `COUNT_IF`, widget-level filters or `COUNT(*)` in widget expressions.
  - Severity colours are pinned (HIGH `#d03b3b`, MEDIUM `#ec835a`, LOW `#fab219`, PASS `#0ca30c`) and always shown
    with a text / icon label.
- **Optional system tables:** reference them as `${source:system.x.y}` in `10_sources.sql`, add their columns to
  `OPTIONAL_SOURCES` in `src/refresh.py`, and always give them an alias. CI fails if a fallback is missing.
- **Descriptions:** every table / view has a `COMMENT`. The Genie agent relies on these descriptions, so keep them
  accurate.
- **Generated files** (`src/dashboards/*.lvdash.json`, `src/genie/*.genie.json`) are committed, so the bundle deploys
  without running the generators. CI fails if they are stale. Placeholders filled by `src/publish.py`:
  `${catalog}` / `${schema}` (Genie tables and SQL) and `${genie_space_id}` (the dashboard's Ask Genie agent).
- **Why the dashboard and the agent are not bundle resources:** creating a Genie space fails unless every table
  exists, and the tables are only created by the job, so a first Deploy could never succeed. The publish task
  creates them after the refresh, keeps their ids and a content hash in `published_assets`, and only updates them
  when the template or settings change.
